# 合作项目数据收件箱

本项目维护合作项目数据收件箱的领域约定、角色边界与样例数据，并提供从零实现的完整收件服务，供后端服务、接口和自动化验证统一使用。服务覆盖合作院校填报员、数据协调员、报告编制人员三类角色，并落实多格式映射、隔离错误、原子发布、来源谱系四条关键约束。

## 收件服务能力

- **先指纹后处理**：文件一到先保存 SHA-256 指纹、提交方、字段映射版本与规则版本；重复文件只登记并指向原批次，绝不重复入库。
- **多格式映射**：支持 CSV / TSV / JSON，字段映射按版本管理、按提交方适用，可换版、可停用；批次永久绑定接收时的版本，未映射列在回执中显式列出。
- **逐行校验与隔离**：解析失败整包标记、不产生数据行；行级错误逐行隔离并保留结构化错误码，合格行不再被问题行拖累。
- **受控修订**：只有数据协调员可对隔离行修订，每次修订留痕（旧值/新值/校验结论/序号），修订后立即重新校验。
- **原子发布**：仅「合格」行可由报告编制人员一次性发布；同范围发布经显式闸门串行化，业务键冲突时整批回滚，失败发布只留 `已回滚` 记录，不留半成品。
- **撤回与谱系**：撤回只做状态迁移、不物理删除；每一行都可追溯来源文件、指纹、提交方、映射/规则版本、修订链与正式数据去向（含撤回记录指针）。

## 目录

- `domain/contract.json`：领域角色、状态、约束和样例。
- `src/domain_contract/`：契约读取与确定性校验。
- `src/inbox/`：完整收件服务。
  - `fingerprint.py` 文件指纹；`parsing.py` 多格式解析；`mapping.py` 映射版本；`rules.py` 逐行规则。
  - `model.py` / `errors.py` 状态枚举、收据结构与领域错误。
  - `database.py` SQLite schema、仓储与发布闸门。
  - `service.py` 应用服务：接收、修订、发布、撤回、谱系查询。
- `tools/check_contract.py`：命令行契约摘要检查。
- `tools/demo.py`：端到端流程演示（内存库，可直接运行）。
- `tests/`：契约回归与收件服务回归（含多人并发发布、冲突回滚、撤回、换版）。

## 验证

测试命令：`python3 -m unittest discover -s tests -v`

编译命令：`python3 -m compileall -q src tools tests`

命令行检查：`python3 tools/check_contract.py domain/contract.json`

端到端演示：`python3 tools/demo.py`
